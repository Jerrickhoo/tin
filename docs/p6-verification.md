# P6 verification — debts and user-only reminders

Prepared for main on **2026-10-24 (Asia/Manila)**. P6.1 and P6.2 are implemented locally. No push or deployment was performed. The user's instruction was to implement P6, list review findings, fix them, and repeat the scan until ready for main.

## Delivered behavior

- `/debts`, linked from Upcoming and History, shows separate “I owe” and “Owed to me” totals, person/note search, direction/status filters, original amounts, effective and optional due dates, paid amounts and remaining balances. Settled and canceled records remain available. Multiple debts for the same person retain distinct identities; person labels are immutable snapshots rather than a new contact/address-book entity.
- The existing P2 `FinancialSheet`, `addObligation` and `addRecovery` commands handle lending, borrowing, noncash historical openings, expense-backed claims and partial/full settlements. Debt detail and History use the same outstanding calculation. Each payment opens its exact History chain, and expanded payment details link back to the debt. Voiding a payment reopens the remaining amount.
- Principal remains outside income and purchase-spending totals. Historical openings create no cash. The existing local transaction, FIFO outbox, owner-locked server validation, overpayment caps, origin-link protections, backup/restore and reset paths remain authoritative. P6 introduces no second repayment store and no new migration.
- Upcoming has one reminder queue for debts, subscriptions, installments and opt-in balance checks. D13 defaults: three days before and on the due date; overdue items stay available; a balance check is offered after 30 days or when an account was never checked. Missing debt due dates never create a deadline.
- Snooze lasts three Manila dates. Dismiss applies to the displayed stage and remaining amount; a new due stage or changed remaining amount can resurface the item. Per-item mute remains until explicitly reset. “Mark reminders seen” suppresses repeated Home hints without hiding the queue. Settled, skipped and canceled items do not enter the queue.
- Reminder preferences, snooze/dismiss/mute/seen state are device-local, explicitly labeled, owner-scoped and cleared on logout/reset. The existing server preference schema supports week start only, so P6 uses the roadmap's local fallback. Financial records still sync and use backup format 5. No reminders contact another person, promise closed-app delivery, or call a payment command.
- Patch notes describe P6 as build `2026.10.24.p6`.

## Reproduce and release scope

```text
npm.cmd run check
npm.cmd run build
node --env-file=.env scripts/check-release-schema.mjs
```

For the existing explicitly disposable browser fixture, run `node scripts/serve-p5-staging.mjs`, authenticate with the private fixture, then use the Playwright CLI to run `output/playwright/p6/layout-matrix.js`. The browser verification scripts describe fixture workflows; the creation flow is not idempotent and must not target daily data.

The existing large-bundle build warning remains the roadmap's deferred performance item. Device-local reminder preferences do not follow the user to another device and are not in the financial backup. Existing cross-device reset propagation and physical-device limitations remain recorded for P8. No newly introduced financial or P6 release blocker is intentionally deferred.
