## Release procedure and limits

```text
npm.cmd run check
npm.cmd run build
node scripts/probe-p8-staging.mjs
node scripts/prepare-p8-release.mjs
```

The staging probe resets only its dedicated disposable fixture accounts and rotates their credentials. Do not reuse its financial-creation browser scripts against daily data. `scripts/serve-p8-staging.mjs` builds/serves the guarded production-style fixture at port 5198.

Rollback of the client keeps all financial data/readers and installed migrations. Disable affected entry points or restore the prior compatible client; never drop financial tables or strip queued metadata. Before replacing an old/offline client, back up its pending data, reconnect using a compatible client and verify the queue drains. On reset, back up unsynced entries and sign out on every other device first; those left signed in can retain deleted data or reintroduce pending writes. The update-only sync protocol does not propagate reset deletions.

Physical phone/OS sleep and native picker behavior remain outside Edge emulation and retain the recorded human/device waiver and limitations. The existing large-bundle warning and buried sheet-history marker limitation remain deferred. P8 does not introduce bulk historical tagging, a sync rewrite, an automatic recurring cutover or a deployment. P8.2's actual publication status remains pending until a release commit is pushed and deployment/CI are observed.
